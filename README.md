# ПП · рецепты — редакционная версия 2.0

## Быстрый запуск на ПК

1. Распакуйте весь архив в новую папку. Не заменяйте исходный проект без резервной копии.
2. Откройте `index.html` двойным щелчком в современном браузере.
3. Установка Node.js и интернет для этого варианта не нужны: изображения, шрифты и основной JavaScript локальные.

Для разработки с Node.js 20+:

```sh
npm run dev
```

Откройте http://127.0.0.1:4173. Остановка сервера: Ctrl+C.

```sh
npm run check
npm run build
```

Сборка находится в `dist/`; это содержимое можно разместить на статическом хостинге. Папка dist не включена в архив, поскольку дублирует локальные изображения и автоматически создаётся указанной командой.

## Что изменилось

- Журнальная главная страница, льняной фон, белые карточки, шалфейные акценты, Serif + Sans и адаптивная Bento-сетка.
- Поиск по названиям и ингредиентам, категории, фильтры и пустое состояние.
- 14 действующих рецептов и 21 вариация; адреса исходных страниц сохранены.
- КБЖУ карточек включает калории, белки, жиры и углеводы на 100 г для базовой вариации.
- Селектор от 1 до 20 порций; ингредиенты, диапазоны, дроби и итоговые нутриенты пересчитываются пропорционально.
- Настоящие checkbox-элементы с зачёркиванием, счётчиком готовых продуктов и локальным сохранением по рецепту/вариации.
- Режим готовки с крупными шагами, прогрессом, Escape, клавиатурной навигацией и возвратом фокуса. Поддержка удержания экрана включённым зависит от браузера и защищённого контекста.
- Учитывается reduced motion. Работают открытие файлов напрямую и запуск через сервер.
- Правила дальнейших изменений: `.antigravity/rules.md`.

## Архитектура

Исходник был набором самостоятельных HTML-файлов без React, Tailwind, TypeScript, package.json и линтера. Основная версия сохраняет статическую архитектуру вместо ненужной миграции.

- `assets/styles.css` — дизайн и адаптивность.
- `assets/app.js` — каталог, фильтры, порции, чек-листы и режим готовки.
- `assets/recipes-data.js` — ингредиенты, КБЖУ, шаги и вариации из исходных рецептов.
- `assets/fonts/` — локальные Liberation Serif / Sans, лицензия рядом.
- `src/enhancements.jsx` — дополнительный React-слой счётчика с Framer Motion и Lucide.
- `scripts/` — локальный сервер, проверка, сборка и браузерные тесты.

## Framer Motion и Lucide: важное ограничение

Framer Motion, lucide-react, React и инструменты сборки объявлены в package.json; создан дополнительный React-слой. В среде выполнения не было доступа к интернету и установленных Framer Motion / Lucide, поэтому эти пакеты **не установлены**, а расширенная сборка **не проверена**.

Переданная рабочая версия использует CSS-анимации и локальные SVG-иконки. Все основные функции работают без библиотек.

Чтобы установить и включить дополнительный слой на компьютере с интернетом:

```sh
npm install
npm run build:enhanced
npm run dev -- --dist
```

В расширенной сборке Framer Motion управляет микроанимациями счётчика, Lucide — его иконками. Остальные статические элементы сохраняют CSS-анимации. После установки требуется отдельно проверить расширенную сборку; она не входит в результаты тестов основной версии.

## Проверки

- `npm run check`: синтаксис JavaScript, 14 маршрутов, 21 вариация, изображения и структура пищевых данных.
- `npm run build`: автономная статическая сборка.
- Основной вариант: 56 автоматических проверок в Chromium — поиск, фильтры, категории, все рецепты и вариации, порции, нутриенты, чек-листы и сохранение, смартфон 390 × 844, режим готовки, min/max, дроби, диапазоны, упаковки, file:// и reduced motion.
- `test-results/results.json` — отчёт тестов. Превью — в `preview/`.
- TypeScript и ESLint в исходнике не было; это проверка JS-синтаксиса и поведения, а не утверждение о пройденном TypeScript/ESLint-анализе.

Для повторного браузерного тестирования нужны установленные зависимости и Chromium:

```sh
npm install
npx playwright install chromium
npm run dev
# В другом терминале:
npm test
```

При необходимости задайте путь к браузеру через CHROMIUM_PATH. Тесты не запускают отправку сообщений или работу с внешними сервисами.

## О пищевых данных и пересчёте

КБЖУ перенесено из исходника, без независимой диетологической верификации. В исходных значениях есть округления; показатели на 100 г и итог блюда могут отличаться из-за округлений/оценки готового веса. Для диапазона «4–6 порций» базой пересчёта принято 4; для сочников — 8 штук; для хлеба — число ломтиков исходной вариации.

КБЖУ на 100 г не меняется при увеличении объёма. На одну порцию сохраняется фиксированный размер; изменяется количество приготовленных порций и итоговый КБЖУ. Диапазоны ингредиентов сохраняются; массу одной упаковки после «по» не масштабируем. Дробные яйца/ложки показываются числом: для точного приготовления яйца можно взвешивать.

Граммовки в повествовательных шагах остаются исходными — об этом есть заметная подсказка. Пересчитанные количества находятся в ингредиентах. Температура и время не масштабируются автоматически: при другом объёме необходимо учитывать форму и проверять готовность.

Фильтр «Без сахара» означает отсутствие добавленного сахара, а не отсутствие природных сахаров. Кето-подборка не является рекомендацией рациона. Сложность — редакционная оценка, а не данные нутриентного расчёта.

## Безопасность и исходные инструменты

Сайт не содержит Telegram-токенов и не отправляет данные во внешние сервисы. Старый персональный PowerShell-инструмент `tools/send_tg.ps1` и инструкции с личными идентификаторами не включены в обновлённый архив; при необходимости сохраните этот инструмент отдельно из исходного архива. Интеграция Telegram в новой веб-версии не реализована. Исходные изображения сохранены; права на них остаются ответственностью владельца проекта.

Приложению нужен включённый JavaScript. Это статический клиентский сайт, без учётных записей, базы данных или серверного API.
