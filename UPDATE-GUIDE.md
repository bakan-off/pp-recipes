# Как обновить pp-recipes

Архив подготовлен для репозитория https://github.com/bakan-off/pp-recipes.
Он основан на коммите `a74fe10a3efc01b3ca2e399de4dd4d0462991456` ветки main. Если после этого коммита добавлены рецепты или внесены другие изменения, не затирайте их: сначала сравните изменения и перенесите новые рецепты в `assets/recipes-data.js`, затем пересоберите сайт.

## 1. Сделайте резервные копии

1. На GitHub откройте репозиторий → **Code → Download ZIP**. Сохраните исходную версию отдельно.
2. Если в браузере есть важные избранные рецепты, рацион или покупки, не очищайте данные сайта. Обновление сохраняет прежние ключи избранного, корзины, рациона и темы. Новая «Моя кухня» позволит скачать резервную копию.
3. Ничего не удаляйте из существующей папки `.git` и не создавайте новый репозиторий поверх старого.

## 2. Сначала посмотрите локально

1. Распакуйте архив. В папке `pp-recipes` находятся готовый сайт и исходники. Именно **содержимое этой папки**, а не внешнюю папку архива, нужно переносить в корень репозитория.
2. Установите актуальную Node.js LTS с https://nodejs.org, если её ещё нет.
3. Откройте терминал в папке `pp-recipes` и выполните:

```sh
node scripts/serve.mjs
```

4. Откройте `http://127.0.0.1:4173`.
5. Проверьте главную, любимый рецепт, свой пересчёт и редактор `http://127.0.0.1:4173/editor.html`.
6. Остановите сервер сочетанием Ctrl+C.

Для просмотра и публикации готового сайта `npm install` не нужен. HTML уже собран. Прямое открытие через `file://` не заменяет запуск сервера.

## 3. Рекомендуемый способ: GitHub Desktop

Он удобнее веб-загрузки: в обновлении много изображений, а веб-интерфейс GitHub ограничивает загрузку большого количества файлов.

1. Установите GitHub Desktop: https://desktop.github.com.
2. Войдите в свой GitHub и клонируйте **bakan-off/pp-recipes**.
3. Нажмите **Fetch origin / Pull origin**, чтобы получить последние изменения.
4. Создайте отдельную ветку, например `personal-kitchen-v3`. Это позволит проверить изменения до замены main.
5. Откройте локальную папку репозитория. Скопируйте в неё **всё содержимое папки `pp-recipes` из архива** с заменой одноимённых файлов.
6. Не копируйте `node_modules/`, `.git/`, `qa-output/` или `dist/`, если создавали их самостоятельно. В готовом архиве их нет. Не удаляйте свой `.git`.
7. В терминале папки репозитория выполните:

```sh
npm run build
npm test
```

8. В GitHub Desktop просмотрите изменения. Особенно проверьте `assets/recipes-data.js`: число рецептов исходного обновления — 34, вариантов — 66. Новые рецепты, которые добавлены вами позже базового коммита, должны остаться.
9. Создайте коммит, например `Personal kitchen: recipe adaptation, editor and mobile refresh`.
10. Нажмите **Publish branch / Push origin**. Создайте Pull Request в main, проверьте список файлов и выполните Merge.

Не добавляйте токены GitHub, пароли и другие секреты ни в HTML, ни в JavaScript, ни в JSON.

## 4. GitHub Pages

Сначала посмотрите текущую настройку **Settings → Pages**.

- Если используется **Deploy from a branch → main → /(root)**, оставьте её без изменений: готовые страницы находятся в корне.
- Если у вас уже настроен GitHub Actions или публикация из другой папки, не переключайте источник наугад. Используйте существующий процесс и передавайте ему содержимое созданной папки `dist/`.
- Дождитесь успешной публикации в **Actions / Deployments**.
- Адрес остаётся прежним: https://bakan-off.github.io/pp-recipes/.

Обновите страницу. Если браузер держит старую PWA, обновите её повторно после завершения публикации. В новой версии появляется предложение «Доступна новая версия сайта → Обновить». Сначала сохраните свою версию рецепта и завершите таймеры.

Если обновление не появляется, попробуйте приватное окно. Не очищайте данные основного браузера без резервной копии: очистка удалит локальные сохранения.

## 5. Обновите описание GitHub

На главной странице репозитория в блоке **About** нажмите шестерёнку.

**Description:**

> ПП-рецепты, которые подстраиваются под вас: пересчёт порций и КБЖУ, замена продуктов, дневной рацион, список покупок и пошаговый режим готовки.

**Website:**

https://bakan-off.github.io/pp-recipes/

About — настройка GitHub, её нельзя обновить простой заменой README. README из архива уже обновлён.

## 6. Проверка после публикации — 5 минут

- Откройте главную на телефоне: шапка компактная, виден быстрый переход к поиску.
- Найдите хачапури. Измените сыр со 180 на 90 г. Другие продукты должны остаться прежними.
- Откройте второй шаг готовки: связанное количество должно быть 90 г, не 180 г.
- Проверьте собственный случай граммовки в скобках. Проценты жирности и температура не должны изменяться.
- Увеличьте число порций, проверьте ингредиенты, КБЖУ и список покупок.
- Сохраните версию, перезагрузите страницу и откройте «Мою кухню».
- Проверьте ваш привычный штрихкод в FatSecret. Числа всех 66 исходных штрихкодов сохранены.
- Откройте знакомый рецепт онлайн, отключите интернет и обновите эту же страницу.
- Проверьте сигнал короткого таймера на своём телефоне с открытым браузером. При заблокированном экране результат зависит от ОС.

## 7. Как добавлять рецепт вручную

1. Откройте **Редактор рецептов** внизу сайта.
2. Создайте новый рецепт, загрузите JSON от ИИ или выберите существующий из каталога.
3. Укажите порции, готовый вес и ингредиенты. КБЖУ каждого продукта берите с этикетки.
4. После изменения состава нажмите **«Пересчитать КБЖУ из ингредиентов»** для каждого изменённого варианта.
5. В шагах используйте **«Вставить продукт»**. Такая ссылка обновляет название и количество при замене. Удалив ингредиент, исправьте отмеченную ссылку в шаге.
6. Посмотрите предпросмотр, скачайте JSON. Новое фото скачайте отдельной кнопкой.
7. Положите фото в корень локального репозитория. JSON можно положить рядом или в другую папку.
8. Запустите:

```sh
node scripts/add-recipe.mjs my-recipe.json
```

9. Проверьте сайт, закоммитьте и отправьте изменения в GitHub.

Редактор не является серверной админкой. Он готовит файлы, но не публикует их в репозиторий автоматически. Это позволяет не хранить секреты в публичном сайте.

## 8. Если нужно откатиться

Через GitHub выполните **Revert** Pull Request с обновлением и дождитесь повторной публикации. Не используйте Force Push и не переписывайте историю без необходимости. Сохраните копию личных данных: старая версия не умеет показывать новые именованные версии, но откат сам по себе не удаляет их из браузера.
